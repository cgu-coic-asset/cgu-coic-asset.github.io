# 05 交接 SOP（B：沿用同一個專用帳號）

系統存放在單位專用 Gmail。交接時**帳號不變**，只換掉能登入這個帳號的手機、驗證器與備用碼，並更新系統裡的 Super 名單。使用者、網址、QR 貼紙都不受影響。

> 帳號被停權或救不回來時，改照 [重建步驟](../重建步驟.md)（A 方案）。

## 交接前（舊 Super）

1. 系統「系統維運」→「立即備份」，再按「下載最新備份」，存一份在交接用的隨身碟或系辦電腦。
2. 確認 NAS 同步正常，按「NAS 已同步」。
3. 處理完逾期未還、待結案的異常案件（或寫成交接清單）。
4. 準備：專用 Gmail 密碼（彌封信封）、備用碼信封、本手冊。

## 交接當天（新舊 Super 同時在場）

| # | 項目 | 做法 | 完成 |
| --- | --- | --- | --- |
| 1 | 專用 Gmail 登入 | 用舊 Super 的裝置登入專用 Gmail | ☐ |
| 2 | 兩步驟驗證 | 加入新 Super 的手機與驗證器 App；移除舊 Super 的手機與驗證器 | ☐ |
| 3 | 密碼 | 改新密碼，新 Super 自己保管 | ☐ |
| 4 | 備用碼 | 重新產生備用碼並列印，舊的作廢；彌封交系主任或系秘保管 | ☐ |
| 5 | 復原資訊 | 復原信箱仍是系辦公務信箱；復原手機改新 Super | ☐ |
| 6 | 系統 Super | 「帳號」新增新 Super 的 Google 帳號（等級 Super、啟用）；新 Super 登入確認看得到「系統維運」 | ☐ |
| 7 | 舊 Super | 舊 Super 改為 Admin 或「停用」（不刪除） | ☐ |
| 8 | GitHub | `cgu-coic-asset` 組織加入新 Super 為擁有者（至少兩位擁有者） | ☐ |
| 9 | Google Cloud | OAuth 專案（專用 Gmail 擁有）不需變更；確認新 Super 知道位置 | ☐ |
| 10 | NAS | Cloud Sync 仍連專用 Gmail；NAS「借用」資料夾權限改給新 Super | ☐ |
| 11 | 核對 | 新 Super 開「系統維運」：最近備份成功、容量正常；開「操作紀錄」能查詢 | ☐ |

## 交接後

- 在「系統設定」試算表的「交接紀錄」分頁記一列：日期、舊 Super、新 Super、項目「B 交接」、核對結果、備註。
- 隔月 1 號確認新 Super 收到月度提醒信。
