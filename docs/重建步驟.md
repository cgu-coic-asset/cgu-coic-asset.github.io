# 從零重建步驟

適用情況：存放帳號被停權、救不回來，或要搬到新的 Google 帳號（交接 A 方案）。
照這份文件可以從一個全新的 Google 帳號重建出「能登入、資料表為空」的系統；資料搬遷用交接精靈（之後補）。

> 一般交接（B 方案：沿用同一個專用帳號、只換手機與驗證器）**不需要**這份文件。

本文件不寫任何密碼、token 或帳號 Email；以 `<專用 Gmail>`、`<一等管理者 Email>` 表示。

---

## 0. 準備

- 一台 Mac 或 Windows 電腦，安裝 [Node.js](https://nodejs.org/)（LTS 版）與 git。
- 一個**只登入專用 Gmail** 的瀏覽器設定檔（Chrome「新增設定檔」）。同時登入多個 Google 帳號時，Apps Script 很容易開錯帳號或授權錯帳號。
- GitHub 帳號，且是 `cgu-coic-asset` 組織的擁有者。
- 本 repo 的程式碼：`git clone https://github.com/cgu-coic-asset/cgu-coic-asset.github.io.git`

## 1. 專用 Google 帳號

1. 到 <https://accounts.google.com/signup> 選「個人用途」建立帳號；生日填成年人日期並記下；手機驗證（才有完整 15 GB）。
2. 安全性設定：兩步驟驗證用 Google Authenticator＋列印備用碼（彌封保管）；**不建立密碼金鑰**；復原信箱設系辦公務信箱；開啟「閒置帳戶管理員」（6 個月通知系辦）；不開進階保護計畫。

## 2. Google 登入用的 OAuth 用戶端

在專用 Gmail 的瀏覽器設定檔操作。

1. <https://console.cloud.google.com> → 建立專案（名稱自訂）。**不要**按「免費試用」。
2. 搜尋「Google Auth Platform」→「開始使用」：
   - 應用程式名稱「資產管理系統」，支援 Email 選專用 Gmail
   - 目標對象：**外部**
   - 「應用程式網域」全部留空，**不要上傳標誌**（會觸發 Google 審查）
3. 「目標對象」→「發布應用程式」。
4. 「用戶端」→「建立用戶端」：
   - 應用程式類型**必須選「網頁應用程式」**（選錯就不會出現 JavaScript 來源欄位）
   - 已授權的 JavaScript 來源：`https://cgu-coic-asset.github.io`（本機測試另加 `http://localhost`、`http://localhost:8000`）
   - 重新導向 URI 不用填
5. 複製**用戶端 ID**（`….apps.googleusercontent.com`）。

## 3. Apps Script 專案與 clasp

1. 專用 Gmail 開 <https://script.google.com/home/usersettings> → 「Google Apps Script API」切到**開啟**。生效可能要等 5 分鐘以上。
2. 安裝 clasp：`npm install -g @google/clasp`
3. 登入 clasp：在**終端機**執行 `clasp login`，把網址貼到專用 Gmail 的瀏覽器設定檔授權。
   （在 Claude Code 裡用 `!` 執行無法互動輸入，要開獨立的終端機視窗。）
4. 確認登入帳號：`clasp show-authorized-user`
5. 在 repo 根目錄建立新專案（會覆寫 `.clasp.json` 的 scriptId）：
   ```
   mv .clasp.json .clasp.json.old
   clasp create-script --type standalone --title "資產管理系統" --rootDir gas
   ```
   建立後把 `.clasp.json.old` 裡的 `filePushOrder` 搬回新的 `.clasp.json`，再刪掉 `.clasp.json.old`。
   clasp 可能會把 `gas/appsscript.json` 換成預設內容，用 `git checkout gas/appsscript.json` 還原。
6. 第一次推送並建立部署：
   ```
   node --test shared/*.test.js
   for f in shared/*.js; do case "$f" in *.test.js) ;; *) cp "$f" "gas/shared_$(basename "$f")";; esac; done
   clasp push --force
   clasp create-deployment --description "重建"
   ```
   記下輸出的部署 ID（`AKfyc…`）。

## 4. 改設定（三個地方）

| 檔案 | 改什麼 |
| --- | --- |
| `deploy.sh` | `DEPLOYMENT_ID=` 換成新的部署 ID |
| `gas/Config.js` | `OAUTH_CLIENT_ID` 換成第 2 步的用戶端 ID |
| `gas/Setup.js` | `INITIAL_ADMIN_EMAIL` 換成 `<一等管理者 Email>`（用來登入系統的帳號，不是專用 Gmail） |
| `web/config.json` | `apiUrl` 換成 `https://script.google.com/macros/s/<部署 ID>/exec`；`clientId` 換成用戶端 ID |

改完執行 `./deploy.sh "重建設定"`。

## 5. 授權與初始化

1. 專用 Gmail 開 Apps Script 編輯器（網址加 `?authuser=<專用 Gmail>`）。
2. 左側 `Setup.gs` → 函式選 **authorize** → 執行 → 授權畫面**全部勾選**（包含「連線到外部服務」）。
3. 函式選 **setup** → 執行；再執行一次，第二次應全部顯示「沿用」。
4. 雲端硬碟應有「資產管理系統」資料夾，`資料` 內有 5 個試算表（系統設定、固定資產、保管品、作業、LOG_年份）。

## 6. 前端上線

1. `git add -A && git commit -m "重建：更新設定" && git push`
2. GitHub Actions 部署完成後（約 1 分鐘），開 <https://cgu-coic-asset.github.io/>。

## 7. 驗收

| # | 操作 | 應該看到 |
| --- | --- | --- |
| 1 | 用 `<一等管理者 Email>` 登入 | 右上角顯示「一等」，有「系統（一等）」選單 |
| 2 | 開「管理者」 | 名單有自己那一列 |
| 3 | 重新整理 | 仍是登入狀態 |
| 4 | 開 `/?F0000000000` | 顯示資產頁框架 |

## 8. NAS（Synology Cloud Sync）

DSM → Cloud Sync → 新增 Google Drive，以專用 Gmail 登入：

- 遠端路徑：「資產管理系統」整個資料夾
- 同步方向：**僅下載遠端變更**
- 勾選「將 Google 線上文件轉換為 Microsoft Office 格式」
- 勾選「來源刪除時不刪除目的地檔案」
- NAS 開啟快照；「借用」資料夾權限只給一等管理者

## 若 GitHub 組織也要重建

1. 用個人 GitHub 帳號建立免費組織 `cgu-coic-asset`（名稱若被占用，QR 貼紙網址會失效，必須重印）。
2. 組織內建立 **Public** repo `cgu-coic-asset.github.io`，不要勾選任何初始檔案。
3. repo「Settings → Pages」來源選 **GitHub Actions**。
4. 推送：新組織會擋既有的 git 登入。到 <https://github.com/settings/tokens/new?scopes=repo,workflow&description=cgu-coic-asset> 產生 classic token（勾 `repo`、`workflow`，效期 1 年），在終端機推送時以 token 當密碼。
   建議先執行 `git config --local credential.useHttpPath true`，讓這個 repo 的登入與其他 repo 分開保存。
5. 至少加入兩位擁有者。

## 常見問題

| 狀況 | 原因與處理 |
| --- | --- |
| 開 Apps Script 顯示「目前無法開啟這個檔案」，網址有 `authuser=2` 之類 | 瀏覽器用錯帳號；網址加 `?authuser=<專用 Gmail>` |
| `clasp` 回「User has not enabled the Apps Script API」 | 開關開在別的帳號，或還沒生效；確認帳號後等幾分鐘 |
| 後端回「系統發生錯誤」（INTERNAL），剛加了新功能 | 新權限未授權；在編輯器執行 `authorize()`，全部勾選 |
| 登入後後端回「Code.gs／設定尚未設定」或 aud 不符 | `gas/Config.js` 與 `web/config.json` 的用戶端 ID 不一致 |
| `/exec` 的行為沒更新 | 改完要用 `./deploy.sh`（更新同一個部署），不是只 `clasp push` |
| 推送 GitHub 回 403 | 見上方「若 GitHub 組織也要重建」第 4 點 |
| 用 curl 測 POST 失敗但瀏覽器正常 | curl 不要加 `-X POST`（跟隨轉址時會保持 POST） |
